## Next task: the pipeline (biggest remaining lever)

Split the synchronous layer functions into `_begin` (attention -> GR ->
router -> SYNC1 -> fire experts -> shared expert) and `_finish` (SYNC2 ->
collect -> reduce -> GR write), then interleave:

    begin(A,L)  begin(B,L-1)  finish(A,L)  finish(B,L-1)  begin(A,L+1) ...

B is one layer behind A, so B's begin (attention/router/local work) runs
while A's remote expert chain is in flight. For prefill the same works with
chunks instead of tokens: chunk C+1 layer L only needs chunk C's layer-L
QSA records, so a 1+ layer skew satisfies causality. Expected: ~1.3–1.5x
decode and ~2–2.5x prefill. This is the foundation MTP builds on.

Per-frame state to duplicate (front-half transients stay shared; Vulkan
queue ordering protects them): `pending_write` (or flush immediately to
remove it), `injection`, `shared_output`, `shared_scalar`, `reduced`
(moe_reduce output), `hyper_output`/`hyper_output_b` ping-pong, `expert_ids`
and `gates`, the dispatch/collect context, and residual/output pointers.
Slot 0 keeps existing fields so prefill/tests are untouched; slot 1 gets
small dedicated tensors. The executor arena is sized for the 128-token
prefill microbatches, so per-frame decode tensors are kilobytes, not MB.

Functions to thread a slot through: `fg_owner_decode_layer_async`,
`fg_owner_gr_read_batch` (injection output), `owner_shared_expert`
(shared_output/scalar), `fg_owner_moe_reduce` (reduced/shared inputs),
`defer_gr_write`/`flush_gr_write` (or drop deferral), and the runtime token
loop in `coordinator_decode_token_local`. A parallel `_begin`/`_finish` for
`fg_owner_prefill_layer` enables the chunk skew.

## After the pipeline (ordered)

   batch), batch selection across query tiles, kill host readbacks. 16K

   per QSA layer.

   prefill. Fuse GR/router/quantize, keep one fence per layer, consider the

3. Microbatch sizing: rank-0 scratch is 192 MiB @128 / 320 @256 / 576 @512;

   `native-262k-microbatch-128` profile exists; a new profile plus manifest
   upgrade is needed (weights unchanged).
4. MTP: 2–3x effective by reusing common and expert weights across verify
   tokens. This is the road to 50+ decode.
