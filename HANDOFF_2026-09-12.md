## Why the reshard is neutral-not-negative

The classic 4x128 layout already fanned out per layer in parallel, so the
round-trip count per decode step was already one, not four. Single-owner's win is
structural headroom: expert dispatches are one message per layer, transport
budget freed, and worker arenas are layer-local. That headroom is what allowed
four frames (50.95) where three was the previous max.

## Where the time actually goes now

Rank 0 runs the common path for all 48 layers through its replicated arena and
dispatches expert work to layer owners. At 50.58 TPS the completion interval is
2.53 s per 128-token batch; with four frames in flight this is consistent with
rank 0's GPU serialising ~0.6 s of common-path work per batch and 4 frames only
hiding transport. Workers are mostly idle during common path. Sept 3 kernel
profile (rank 0, per 128-token stage): experts 252 ms, GDN projections 153 ms,
f32 gr reads 67 ms, router 36 ms, QSA 28 ms.

## Next steps, in order of expected multiplier

1. **Distribute the common path** (the 200 TPS lever). Each rank executes its six
   owned layers and hands the 5.2 MB hyper state to the next rank, instead of
   rank 0 executing all layers. The `fg_layer_work`/`fg_layer_result` protocol
   and `manifest->layer_owner` already exist; the old `src/stage.c` did exactly
   this and was removed by this branch's refactor. Until this lands, rank 0's
   24 CUs cap prefill near ~55 TPS regardless of frame depth.
2. **Second QSA queue limit** blocks 5-8 frames: after raising
   `FG_QSA_REPLICA_DEPTH` to 64, six frames still backpressure. Next suspect is
   the owner writer queue in `runtime.c` (~line 800,
   `"QSA owner writer queue is backpressured"`). More frames are worth
   +8-15% at most once rank 0 is not the bottleneck, so do this after (1).
3. Kernel cuts against the profile above, largest first: expert grouped kernels,
   GDN projections, the f32 gr reads (cooked routing shipped but measured
   neutral because those weights are runtime-cooked already), router.
4. Decode (9.5 short, 7.4 at 4K) needs layer-pipelined token flow or MTP
   (MTP frozen by request). Per-layer decode totals ~2.0 ms with sync1 0.8 /
   collect 0.7; 48 layers x 2 ms = the observed ~10 TPS.

## Pitfalls rediscovered

- `flash-gordon pack` refuses to write into a non-empty output dir; pack to a
  fresh dir and copy shards in.
- A pack with `--expert-map` is only as good as the map file; verify the map's
  sha and keep it with the pack (the placement experiment lost its map).
- `prefill route partition count mismatch` was the collapsed-group bug: routes
  must be deduplicated by rank because single-owner layers repeat the owner in
  all four `layer_groups` slots.
- QSA backpressure errors require a session reset; restart the fleet, not just
  the request.
