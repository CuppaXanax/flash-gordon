# Flash Gordon scope and architecture audit

Audited source: `35b5389` on `codex/expert-parallel-forward`, plus the referenced
task “Explain top_k limitation.” This is a static, targeted audit, not a numerical
correctness certification or fresh fleet benchmark. No runtime changes, fleet
actions, commits, or historical resets were performed during that audit. The
subsequent EP-only implementation is recorded in PRD.md; findings below describe
the audited revision and are not a claim that its retired paths still exist.

## Assessment

The recovery PRD preserves the desired EP architecture but did not specify the
complete eight-device, Q4, native-context, multimodal, MTP product. It is useful
as a recovery work breakdown, not sufficient as a finish-line contract. The
consolidated PRD.md now specifies implementation decisions without claiming they
have been implemented.

Follow-up source tracing corrected the initial priority assessment: EP uses
parallel block scoring plus hierarchical selection; the serial resident selector
is a separate path. EP QSA prefill still processes attention per token. Cooked EP
expert prefill uses individual pair scheduling, while the grouped cooked helper
is restricted to stage-local weights. These batching gaps, together with shared
expert computation before dispatch, are concrete repair targets. The consolidated
PRD replaces the earlier measurement-first sequence.

## Findings grounded in the current source

1. **Per-layer concurrency tradeoff.** `include/fg.h:14-18` fixes eight
   ranks, 128 experts per participating rank and a four-rank group. In
   `src/topology.c`, `ep_delta={0,1,3,5}`, `fg_topology_build` and
   `fg_topology_assign_round_robin` distribute each layer's 512 experts over only
   four owners. All eight can participate across layers, but not at once in a
   layer's routed computation. The user clarified that eight is the intended
   deployment; four additional blades are reserved for supporting models. The
   rank count is therefore correct. Four-owner grouping is not by itself a bug:
   widening it trades expert compute against network and synchronization costs.
   Assess that tradeoff from existing evidence before changing placement.
2. **Batched EP prefill exists.** `src/runtime.c:1877` implements a coordinator
   microbatch through all 48 layers; chat prefill calls it near line 2809.
   It would be inaccurate to say prefill was never built. However,
   `dispatch_prefill_experts` near line 355 executes local work inline while
   iterating routes, before all remote sends have necessarily occurred, then
   receives peers in route order. Dispatch remote work before blocking local
   execution and use readiness-based collection with bounded buffers. Validate
   actual overlap rather than merely checking message types.
3. **Several common prefill projections miss existing token tiling.**
   `src/owner.c:471` uses generic Q8 dense calls for GDN projections; the cooked
   dispatcher in `src/vk.c` has separate ordinary and token-tiled implementations.
   Route eligible batched shapes to the tiled implementation, preserving format
   checks and numerical tests. This is a concrete optimization candidate, not
   evidence of a particular speedup.
4. **A QSA selector has an obvious parallelism bottleneck.**
   `shaders/fg_qsa_resident_select.comp:60` loops over 4,096 blocks within one
   workgroup and then sorts 4,096 scores. Hierarchical parallel scoring/selection
   is a credible replacement, with exact top-512/tie/causality reference checks.
   Establish which selector the EP profile actually invokes before attributing
   historical pipeline QSA timings to EP. Include 2,048/2,049 and
   16,384/16,385 boundary cases and partial blocks.
5. **Q4 is currently a mixed-precision label.** README's pack commands use
   Q4_K_XL. `PERFORMANCE_TRACE_10_035TPS.md` describes Q4_K/Q5_K gate/up,
   Q5_1 down, and Q8 common projections. Their byte and compute costs cannot be
   budgeted as uniformly 0.5 byte per parameter. Quantized-reference parity and
   quantization quality relative to the source model are separate gates.
6. **Storage and coordinator feasibility are underspecified.** The PRD names page
   owners but had no NVMe service budget. Current QSA schema stores 544-byte K,
   544-byte V, 136-byte index key and 12-byte position per token per QSA layer:
   1,236 bytes. At 262,144 tokens across 12 QSA layers that is about 3.62 GiB
   of logical records before page padding, mirrors, index duplication or caches.
   A full 2,048-selected-token read across 12 layers is about 28.97 MiB/token
   before page amplification. Cache hit rate and placement therefore matter
   materially; this is byte arithmetic, not a measured IO rate.
7. **Recovery excludes required deliverables from its definition of done.**
   The prior multimodal/MTP section merely deferred them. Acceptance must include
   media preprocessing/positions and speculative rollback of recurrent state,
   not just feature flags or successful draft generation.
8. **Documentation still contradicts itself.** README advertises a pipeline
   launch path and an 8K boot profile. The runtime still includes pipeline
   orchestration. The PRD commit changed the specification only. R0-R2 are real
   outstanding work, not completed recovery.

## What the performance evidence establishes

The historical EP trace documents roughly 10 TPS on one short greedy workload,
with substantial coordinator time and four-owner routing. It is useful historical
context, not long-context qualification. The referenced task
reports approximately 353 GB/s per blade in component tests. The named local
ceiling-result directory yielded no raw files in this audit, so that measurement
was not independently verified here. No new TPS forecast is justified.

For raw decode use a dependency-aware budget:

`token time = embedding + sum(layer critical paths) + output/sampling`.

Each layer includes mandatory common work and dispatch/reduction, with shared
expert work overlapping remote service only when the implementation actually
allows it. Remote service is bounded by the slowest participating owner and by
coordinator NIC serialization, queueing and storage. Aggregate fleet memory
bandwidth is not available to the coordinator's sequential common matrices.
At 50 TPS the entire token has 20 ms; at 100 TPS it has 10 ms. CU unlocking
does not multiply memory, network, or storage bandwidth by 40/24.

## Minimal path to agreement and implementation

1. Keep the intended eight-device scope. Four supporting blades remain outside
   this deployment. Explain quantization exceptions without silently changing them.
2. Use existing evidence and prior art to resolve the EP design and account for
   memory and critical-path costs as ordinary engineering work. No fresh baseline
   or standalone budgeting project is a prerequisite to fixing known defects.
3. Remove pipeline orchestration and close EP prefill dispatch, tiled projections,
   relevant QSA selection and API correctness in coherent forward changes. The
   agent owns code review and focused testing; the user is not the code reviewer.
4. Reuse existing verification tools. Request new measurements only for a concrete
   unresolved decision or to validate completed work, explaining why existing
   evidence is insufficient. Do not introduce a new qualification framework or
   require another context sweep for every change. Fleet operations still require
   the user's direction.
5. Deliver native context, multimodal and verified MTP. Report actual performance
   clearly when available, separating raw decode from accepted speculative output
   and cold from append prefill. Keep the implementation readable throughout.

The ingredients are established inference techniques, but their integration on
this APU/fabric/storage configuration remains substantial engineering. A static
audit can remove avoidable experimentation; it cannot prove maximal TPS.
