## Offline latency model

The [machine-readable report](mtp-local-chain.json) retains every term,
measurement provenance and source-input hashes. The point estimate is
**99.815711ms/code round**, with **104.565020ms** when target service rises10%.
Projected code throughput is **32.464892TPS** at current simulated yield,
or **33.929194TPS** at the different historical live-ring code yield.
Neither is a serving measurement or60TPS claim.

The model uses47.49309ms summed trained N4 owner medians and18.242224ms
proportional N4 transport. The transport receipt measures actual F32
framing/CRC/validation but only N1 frames; N4 amortization is unmeasured.
It additionally budgets measured local drafting/full-head calls, calibrated
cross-cohort N1 residual, conservative full-frame-equivalent RPCs, state-only
snapshot/retention, native KV repair and1.5ms assumed host/lookup overhead.
No target-transformer overlap or FP16/BF16 transport saving is credited.
The historical158.370ms repair-round cohort is not an isolated repair cost;
this report does not claim a measured158→99.8ms reduction.

Acceptance simulation consumes `min(accepted+1, remaining)` and skips to
the next frontier: code5120 tokens/1580 passes, chat5120/2140.
Raw all-prefix acceptance is not the appropriate online denominator.
N4 numerical differences and changed free-running prefixes can alter it.

## Correctness and memory gates

The new fail-closed gate requires complete actual HTTP/runtime emission
receipts, pass-local target argmax, exchanged same-prefix top2 winners with
**both raw margins<0.10**, and N4 full-vocabulary original-Q8
`mean KL<=0.005`, `top1>=0.985` on exactly80 pinned contexts.
At least79/80 top1 matches are required. The480-natural cohort has a separate
p99 gate and cannot be substituted. Diagnostic identity reports always remain
unqualified. Full new-gate serving capture and N4/Q8 model quality are pending;
selected historical failure prefixes do not satisfy either.

The full Q8 head adds676,920,320 requested-live bytes. With the new
single-session journal, authentic rank7 residency projects14,660,611,624B at
700MiB QSA cache, above the14,495,514,624B cap. The paired single-session
diagnostic plan proposes440MiB off/on, projecting14,387,981,864B and
107,532,760B headroom. Driver-pool overhead is not included, eager admission
must still pass, and neither full-target nor long-context/dual-session fit is
measured. Original service settings remain the restoration target.

Native sessions use replay slots8/9 and10/11; shared vocabulary uses12.
Total slots12→13 reserve an additional512 descriptor sets/8192 storage
descriptors plus command/fence metadata even with MTP off. Switching private
native sessions rebinds/re-records the shared vocabulary graph.

## Reproduction and release

Build `tools/bench-mtp-chain` and run it with authenticated capture, manifest,
native overlay and embedding inputs. It checks independent current GPU draft
IDs and emits per-round timing/repair JSON.
`tools/bench-decode-fusion --state-commit-test` with the sealed small-N flags
provides the existing24 state fixtures plus snapshot/retain timer fields.
The weight-free supplemental archive retains source/binaries/SPIRVs,
CPU/GPU/TCP logs, earlier negative attempts and hash receipts. Its outer
`analyze.py` validates the sealed source inputs and recomputes this model.
No trained weights are committed. Cleanup/publication identities are recorded
in the machine-readable report. A new serialized diagnostic lease is required
before any production measurement; no model-quality waiver is implied.
