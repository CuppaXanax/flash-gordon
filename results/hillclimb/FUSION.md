# Decode fusion: replay-faithful six-layer experiment

**Result: 2,695.01 -> 2,678.59 us/rank block, a 16.42 us (0.61%) win,
not the requested >=30%. No production promotion.** Dispatches at the measured
context fall **214 -> 190**; fewer dispatches are not proportional time savings.
All three fusions remain behind `FG_DECODE_FUSION`, unset/off by default.
Base: `origin/main a63a166`; branch: `cuppaxanax/decode-fusion`.

## Scope and reproducibility

Only `192.168.42.51` was used. `.50` and its embedding/reranking service, and
`.42`–`.49`, were untouched. The physical blade is the user's 40-CU BC-250;
the stale Vulkan 24-CU enumeration is not treated as its real CU count.

`tools/bench_decode_fusion.c` constructs **synthetic, nonzero weights**, not
weights from a pack. It invokes the actual owner/expert/QSA code for owner-local
layers **6–11: GDN, QSA, GDN, GDN, GDN, QSA**. Shapes include hidden 2560,
hyper 4x2560, all 512 experts and real top-10 GPU routing. Expert gate/up is
cooked Q4_K, down cooked Q5_1; dense is selected compact/wide Q4_K or IQ4_NL
for K=320/640. The Q8 control uses cooked Q8 dense. BF16 index projections and
F32 router, norms and recurrence parameters retain their production formats.
The Q4 block has 9,739,403,264 manifest weight bytes (about 9.74 GB).

Matrices are separately seeded by tensor; each expert slab repeats one
matrix **at distinct physical expert addresses**, not one aliased matrix.
This exercises the real shapes, kernels and routing, not real-model quality
or representative expert diversity. Norm weights are one; other parameters
are small finite values. Changing synthetic input is supplied each token, as
a rank would receive activations, rather than generated by a full-model loop.
No PLE, exceptional-layer formats, long-context routing, ring transport,
coordinator, logits head, MTP, pack validation or model KL is measured.

The benchmark calls `fg_owner_decode_block_chained`, keeping production-style
GDN static command replay. Two static slots remain recorded throughout all
nonintrusive measured runs. QSA retains its production dynamic recording and
flush behavior; this is **not** a newly static-recorded QSA implementation.

The new opt-in layer clock API records exactly two COMPUTE-stage timestamps
per layer. Query resets/writes live inside recorded command buffers, so
replay is timed too. Queries are read only after the block drains, without
`WAIT_BIT`. The dispatch ledger is captured while recording; it records
shader, grid, push constants, binding spans and barrier requests, not CPU
dispatch timing. It does not enable `FG_DECODE_PROFILE`.

Qualification: 256 warmup tokens, nine windows x 64 measured tokens, three
fresh weight/input seeds, A/B/A per seed. Tokens 256–831 are measured.
For each seed A is the mean of its two baseline runs; then the three paired
rounds are equally weighted. Bootstrap resamples **rounds**, not correlated
individual tokens: 10,000 deterministic resamples, empirical 95% interval.

The final qualification temporarily pins the governor's existing safe range
to its stock maximum, 2000 MHz. It changes only an experiment-local config's
minimum from 1000 to 2000; voltage points and the system config are unchanged.
Both endpoint clock captures show 2000 MHz. An experiment-owned governor PID
is stopped by numeric PID, the stock service is restored, and its original
config is byte-compared. Endpoint captures are not continuous clock/thermal
telemetry. The archived `restored.txt` and final default-path tests show the
stock service active. `/home/xander/hc-fusion/` was removed after downloading
evidence; cleanup again verified the stock config unchanged.

## Implemented fusions and rejected variants

| Bit | Change | Removed per layer | Numerical handling |
|---|---|---:|---|
| 1 | Router top-10 + nine-word tile schedule | 1 dispatch | Same selected IDs, tie-breaking, gates and schedule; subgroup max/min-ID on supported devices, portable fallback otherwise |
| 2 | Shared-expert add + HC residual write | 1 dispatch | Materialized `precise` intermediate retains separate shared-add rounding in tested cases |
| 4 | Shared gate/up projections + SwiGLU | 2 dispatches | Same dot/reduction and SwiGLU order; cooked Q8 or wide-SoA Q4 only, other formats fall back |

The first shared-Q4 implementation used eight rows/workgroup and regressed:
intrusive gate/up/SwiGLU total ~10.5 us became ~15.1 us. The initial
native-governor A/B/A qualification was **2702.98 -> 2703.95 us**, saving
interval **-3.05 to +0.09 us**: inconclusive/slightly worse, not a win.
Early large smoke improvements were clock/order artifacts and are rejected.

The retained Q4 version uses four rows/workgroup (baseline geometry), plus a
projection-loop unroll hint. The router was changed to subgroup maxima and
minimum-ID tie reduction, reducing workgroup reduction barriers. Final
intrusive scoped means are:

* Router + schedule: **9.227 + 1.073 -> 8.640 us**.
* Shared add + residual: **1.013 + 1.140 -> 1.553 us**.
* Shared gate/up/SwiGLU: **4.470 + 4.470 + 0.873 -> 10.967 us**:
  **still a kernel-time loser**, despite fewer dispatches. Bit 4 is research,
  not a recommended setting.

Single, ordered ablations (three windows, seed 5) gave masks
0/1/2/3/4/7 = 2740.54/2659.35/2661.29/2653.93/2672.91/2654.03 us.
Their first baseline differs materially from the subsequent paired runs:
**do not interpret those unpaired differences as causal wins or rank masks
from them**. Only mask 7 has the final repeated A/B/A qualification.

## Dispatch time versus ideal streaming bytes

`fusion-dispatches.csv` lists **every recorded dispatch** with actual geometry,
push constants and a separately collected intrusive scoped mean. That mean
averages repeated invocations of the same scoped shader, sometimes of different
shapes; it is not an individual replay dispatch timestamp. Intrusive profiling
disables static replay, so it is diagnostic, not the service-time authority.
Both diagnostic runs warm up 256 tokens and sample token 256.

Reference time = reference bytes / **450,000 bytes/us** (decimal 450 GB/s).
Dense rows use cooked weight storage; routed weights use **10/512 of each
expert slab**, not the entire binding. Small operations use logical active
dimensions, never their 128-token scratch descriptor capacities. All CSV
dispatches have a reference estimate; activation traffic for weight kernels
is omitted. These are ideal one-pass streaming comparisons, **not DRAM
counters**: caches, per-head reloads, metadata, reduction arithmetic,
dependencies and occupancy can change real traffic/time.

Counted projection/routed weight reads are ~489.54 MB/block, or **1087.86 us ideal**,
already ~42% of the nonintrusive GPU layer sum. Diagnostic GPU envelopes:
2544.68 -> 2525.92 us; measured inter-kernel/submission gaps
107.64 -> 95.08 us (~4% of the original envelope), with 10 submissions both
ways. Gaps are not the whole memory-barrier cost: dependent stalls may occur
inside attributed dispatch time. Removing gaps alone cannot yield 30%.

Tiny HC ops, router reductions, recurrence and QSA barriers are worth targeting,
but the original ~18 us average dispatch figure is **not** pure launch overhead.
Dense projections, routed weights and recurrence contain substantial actual
work. Next candidates are HC norm/injection/down prologues, HC-up/mix epilogues,
GDN alpha/beta pairing, and QSA prepare/quantize/index normalization. They need
geometry/occupancy-aware implementations and fresh replay qualification;
no global barrier relaxation or persistent megakernel is enabled here.

## Numerical and regression gates

On RADV, router tests byte-compare IDs, gates and all schedule words across
ties, random finite logits, NaN, +inf and all -inf. Residual tests observed
zero changed elements (allowed absolute/relative floor 3e-7); Q4/Q8 shared
projection tests observed zero changed elements (allowed 2e-6). The allowance
is documented because compiler/device FMA behavior is not proven universally
bit-exact. Current full-block output hashes and final GDN-state hashes match
within every A/B/A seed, ablation, no-clock, Q8 and diagnostic pair; output
finiteness is checked. Initial short captures additionally byte-compared all
32 x 10240 output floats for masks 0/1/2/4/7; their SHA256 manifest is archived.
Hash equality is not a proof of all inputs or real-model KL.

New RADV tests: `decode_fusion_router`, `decode_fusion_residual`,
`decode_fusion_shared`, `decode_layer_clocks` pass. Layer-clock test verifies
changed inputs across static replay, timing/ledger, and refusal to enable
clocks after static recording. Default-path RADV tests `dense_quant_soa`,
`dense_quant_compact`, `q8_decode_shape_parity`, `batch_submission_parity`,
`pipeline_flush_parity`, `static_batch_replay` pass. Local WSL builds of the
serving binary, benchmark and shaders, Python analysis tests and flag gate
pass. No full Vulkan suite pass or real-model quality qualification is claimed.
**Keep all fusion bits off for production pending pack-backed KL and fleet A/B.**

## Conditional eight-rank projection, not a ring measurement

Do not multiply this 4-GDN/2-QSA block by eight: the model has 36 GDN + 12 QSA.
Type-weighted saving =
`36 * 2.638762 + 12 * 2.907917 = 129.890 us/token`.

Anchoring that *absolute* saving to the historical 29.971 ms rank-service
sum gives 29.841 ms. Holding 2.122 ms prep and 5.344 ms other transport/head
terms fixed gives **37.437 -> 37.307 ms/token**, or **26.71 -> 26.80 TPS**.
This assumes transfer across different weight/context/clock/rank operating
points and is only an illustrative projection, not measured fleet TPS.
The raw synthetic type-weighted GPU sums are 20.150 -> 20.020 ms, demonstrating
why substituting this benchmark's absolute timings for the real ring is invalid.
The >=30% service-time target and 60+ TPS goal are **not reached**.

runner but stages scripts only under `/home/xander/hc-fusion`, not its normal
